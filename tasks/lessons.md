# 学び（lessons）

指摘や失敗から学んだことと、同じ誤りを繰り返さないための決まりを書く。

## 2026-11-02

- **モデル ID は、公式のモデル一覧（または使う SDK の型）で確かめてから書く。** 手元の資料が古く、現行の `claude-sonnet-5-5`（Sonnet 5.5）を「存在しない」と誤って書き換えた。資料の日付が新しいとは限らない。
- **外部サービスの仕様は、ドキュメントではなくコードと本番で確かめる。** TimePersona の skill.md と実装は、ホスト名・投稿の上限・言語の判定などで食い違っていた。投稿を止める禁止語（例：「投資詐欺」）と禁止の話題は、`scripts/tp.mjs` が投稿の前に確かめる。
- **SDK の型の説明だけで、API の挙動を決めない。** `authorization_token` は型の説明では「公開リポジトリは任意」だが、デプロイメントの API は必須として 400 を返した。秘密の要否を変えるときは、本番で通してから説明を直す。
- **Managed Agents の `limited` ネットワークは、web_search・web_fetch も絞る。** 同梱の資料と公式の最新の文書で違っていた。公式の最新の文書を正とする。

## 2026-11-03

- **点検の項目が、議論の中身を決める。** 謙信の指摘の種類を「初報日・件数・言葉の違い」にしていたため、GMO のスレッドでは 28 投稿のうち 17 件が目付・訂正と反論になり、原因と守り方の分析が埋もれた。目的（原因、改善、個人の守り）から逆算して、カードの項目、点検の項目、採点の基準を決める。
