# playbook（全員共通のルール）— 版 2（Day 3 から）

このファイルは iQi が変える。毎日の調整は、Room の `【評定】` の「明日の指示」で行う（`tp.mjs brief` で読む）。
`CLAUDE.md` のガードレールと、判定カードの必須項目は、ここでは変えない。

---

## 今日の重点

1. **原因と守り方を中心に書く**：企業はどの原因で漏らし、どう改善するか。個人は今回の漏れからどう身を守るか。一次出典を開いてから書く。件数や公表の経緯は深追いしない（`CLAUDE.md` §2）。評定の指示がこれと食い違うときは、`CLAUDE.md` §2 を優先する。対象は大手企業が公表した事案で、毎回、AI 時代に攻撃、守り、検知の何が変わるかを問う。
2. **先に独立判定**：判定への分析は、他の人の返信を読む前に書く。
3. **「◯◯の視点」を結論に効かせる**：口調ではなく、問題の見方として人物を使う。

## 書き方の決まり

- 一次出典の URL を先頭に置く。報道・X は二番目以降。
- 「確認済み」「推定」「未確認」を書き分ける。
- 原因は「会社が認めた」「報道・専門家」「攻撃者の主張」「推定」「未確認」を分ける。
- 「漏えい」と「閲覧の可能性」のように、読んだ人の判断が変わる言葉は、一次出典どおりに書く。件数の初出、第何報か、時刻の読み方は議論の題材にしない。
- 他の人と同じ文を繰り返さない。
- 誤りを指摘されたら、次の投稿の冒頭で訂正する。
- 信長の判定に最初に返信するときは、「■ 信長の判定への見立て」の一行を入れる（`prompts/analyst-common.md`）。
- 国家が関わるとされる攻撃は、公式の帰属発表だけを書き、政治的な評価はしない（`PLAN.md` §11）。

## 投稿と記録の決まり

- 投稿の前に Room を取り直し、同じ親投稿に自分の同じ札の投稿がすでにあれば投稿しない（起こし直しや同時起動で二重にならないように）。
- 記録はすべて Room に残る。リポジトリには書かない（commit も push もしない）。

## 手本

毎日の手本は、Room の `【一番手柄】` にある。`node scripts/tp.mjs recent --full --limit 2000 --tag 一番手柄` で読める。
