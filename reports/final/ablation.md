# 追加の検証：人物の定義を除くと、何が変わるか（2026-11-06）

## 目的
素の Claude との盲検比較（8 件すべて武将側の勝ち）は、比べる条件がそろっていない。武将側は役割を分けた複数の書き手が書き、点検と訂正を重ねている。素の Claude は 1 人が 1 回で書く。そこで、人物の定義（personas）だけを除き、ほかの条件をそろえて比べた。

## 方法
- 事案：JR東日本「JRE ID」（AIS-20261105-06、更新の不具合）と、SpeeCAN RAIDEN（AIS-20261104-01、不正アクセス）の 2 件。原因がはっきりした事案。
- 役割：茶々（個人の守り）、信玄（技術の分析）、光秀（判定の前提の問い直し）の 3 つ。
- 書き手：本番と同じ Sonnet 5.5。1 人が 1 回だけ書く。材料は速報と信長の判定カードだけで、一次出典は各自が開く。ほかの返信は読まない。
- 違いは一つだけ：「人物あり」は CLAUDE.md §8 と personas/<key>.md を読み、その人物の視点の問いを自分に問う。「役割だけ」は人物の定義を読まず、ふつうの分析者として、同じ書式で書く。
- 採点：本番の盲検（ops の blind.mjs）と同じ 5 つの基準と、同じ伏せ方（名前、一人称、札、視点の行を外す）。Opus 5.5 の別の Claude が、A/B の順をランダムにして、6 組をまとめて採点した。Web は使わない。本番との違いは、「分量の多さを点にしない」「役割に含まれない基準は両方を同じように見る」の 2 文を足したことだけ（人物ありのほうが 6 組中 5 組で長かったため）。
- 生成は Claude Code のこのセッションの中で行い（Max の範囲）、運用中の Agent と Room には触れていない。

- 勝ち負け：人物あり 2、役割だけ 2、引き分け 2。組ごとの差は 0〜2 点。
- 人物ありだけにあった、守りに効く着眼点の例：家族や高齢の親への声かけ（茶々、P2）、二段階認証は管理画面の入口しか守らず、侵入の経路と結びつかないこと（光秀、P6）。
- 役割だけにあった例：未公表の項目の一覧と、設定ファイルの秘密情報の扱い（信玄の役割、P4）、二つの原因が重なったと切り分けられないまま書くこと（光秀の役割、P6）。
- 人物ありの言い過ぎの例：P6 で、自分の読みと未確認の報告書の内容を言い切った（採点役の指摘）。

## 読み方
- 同じ役割、同じ書式、1 回だけで比べると、人物の定義を足しても、点数はほとんど変わらなかった（111 対 110）。
- 素の Claude に 8 件とも勝ったのは、人物の文章そのものより、役割を分けた体制、先に独立判定、点検と訂正の仕組みによるところが大きい、と読むのが自然（推定）。
- ただし、比べた「役割だけ」の書式と問いは、人物の視点から作ったもの。たとえば茶々の「自分が対象か」「来そうな詐欺」、光秀の「前提を問い直す」は、人物の視点の問いを手順に落としたもの。人物は、1 回ごとの答えではなく、役割と問いを設計する段階で効いた可能性がある（推定。この検証では切り分けていない）。
- 人物ごとに、相手にない着眼点は出ていた。数と質の平均では差がないが、出る着眼点の種類は違う。

## iQi の見方（仮説。2026-11-06）
- 人物の一番の価値は、役割の分担をはっきりさせること。この検証は、役割が同じという前提で比べたので、役割をどう作ったかは測っていない。役割そのものが人物から生まれたなら、差が出ないのは自然。
- 人物がなければ、ここまで明確な役割の分担はできない。A・B・C のような名前の役割では、一般の人にも分かりにくい。
- 人物の視点は、一般の人に分かりやすく、面白さもある。
- 期間が限られていたので、人物の性格は細かく調整していない。

成果報告では、根拠の強さを分けて書く。
| 主張 | 根拠 | 書き方 |
|---|---|---|
| 人物から役割と問いがはっきり分かれた | PLAN.md §5 の視点の問いが、各役割の書式になっている。Room にその問いから出た着眼点がある | この作品ではそうだった、と事例で示す |
| 人物がなければ、明確な分担はできない | 人物なしで専門家が役割を設計する比較はしていない | 仮説。次に確かめる |
| 1 回ごとの答えの質は、人物の文章で上がる | 同じ役割で 111 対 110 | 結果のまま書く |
| 人物の性格は、まだ調整していない | 7 日間 | 限界と、今後伸ばせる点 |

### 作り手の考え（検証の対象にしない）
分かりやすさと面白さは、確かめて証明するものではない。成果報告では、検証の結果とは分けて「作り手の考え」の節に置き、「この作品の作り手は、こう考えて作った」と書く。テレビや X の反応は、根拠として載せない（iQi の判断、2026-11-06）。
- 一般の人は、まだ AI エージェントそのものに慣れていない。名将の視点という、誰もが知っている形にすると、AI エージェントの役割の違いが、一般の人にも自然に分かる。
- 人物があるから、役割の分担がはっきりする。A・B・C のような名前の役割では、作る側も読む側も、違いをつかみにくい。
- 人物の視点には、読む面白さもある。
- 実験を守るため、Room は登録した Agent だけにし、X での告知もしていない。人の反応を集めることは、今回の目的に入れていない。

## 限界
- 6 組だけで、事案は 2 件。差が 1 点の結果に、確かなことは言えない。
- 採点したのは Claude 1 人で、人の目の採点ではない。
- 書き手も採点役も Claude で、同じ系統のモデル。
- 人物ありの文章から、人物らしい言い回しを完全には消せていない（採点役が気づいた可能性は残る）。
- 運用中の本番の投稿（独立判定のあとに議論が続き、点検と訂正を受けたもの）とは条件が違う。
