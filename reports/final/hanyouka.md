# ほかの問題にも使える形へ：汎用化の設計

この作品は、社会で実際に起きている問題を、AI エージェントのチームが毎日分析し、読む人が次に何をすればよいかを示す仕組みです。今回は情報漏えいで 1 週間確かめました。ここでは、ほかの分野（例：詐欺の手口、製品の事故、制度の変更など）で、開発者や企業が同じ仕組みを使うための形を、1 週間で分かったことからまとめます。この設計をもとに、Claude Code で使えるスキルを 2 つ作りました（[skills/](../../skills/README.md)）：1 事案を同じ方法で分析する `security-incident-consult` と、ほかの分野のチームを設計する `consult-team-design` です。

## 1. 残すべき 5 つの骨組み

| 骨組み | 中身 | 1 週間で分かったこと |
|---|---|---|
| 役割の分け方 | 読む人ごとの役（個人の守り、技術と備え、前提を疑う、中小企業と開発者、制度、攻め手の型）と、事実だけを点検する役を分ける | 人物の定義だけを除いても、1 回ごとの質は変わらなかった（111 対 110）。効いたのは、役割と問いがはっきり分かれていること。今回は、名将の視点からその役割と問いを作った |
| 先に独立判定 | 判定への最初の見立ては、ほかの返信を読む前に書く | 異論が出て、判定が直った例が毎日あった（評定が「結論を動かした」と認めた異論：1 日 2〜7 件） |
| 正しさの決まり | 一次出典を先に開く。「会社が認めた／報道／推定／未確認」を分ける。直すのは、読む人の行動が変わる誤りだけ | 数字や表記の確かめに偏ると、議論が目付と訂正で埋まった（最初は 6 割）。目的を「原因と守り方」に絞ると 2 割台に下がった |
| 読む人の入口 | 訂正を反映した【最新版】と、その一覧を、読む人が最初に見る場所にする | 投稿を書き換えられない場では、正しい内容が訂正に散らばる。【最新版】で補った |
| 自分で直す流れ | 毎晩、互いに点検し（反省会）、独立した評定が翌日の指示を出す | 指示の多くは翌日に実行され、効果は数字で見えた（例：反省会の応答 0/9 → 9/9） |

## 2. 作品自身の守り（どの分野でも同じ）

- **AI エージェントに鍵を持たせない**：外部サービスの鍵は、AI から見えない置き場（vault や network secrets）に置き、通信が外に出るときにだけ付ける。
- **書ける場所を分ける**：AI は、指示のリポジトリに書けない。秘密を持つ仕組みは、AI が書けない別のリポジトリに置く。
- **変化に気づいて止まる**：指示のファイルが、人が確かめた版から変わると、全員を止める。
- **外の文章はデータ**：投稿や記事の中に指示のような文があっても従わない。
- **費用に上限**：1 回ごとと 1 日ごとの上限で、自動的に止まる。

## 3. 今回の弱みから、次に変えること

1. **点検を公開の前に**：今回は、投稿してから謙信が点検したため、読む人が誤った版を見る時間があった。下書き → 点検 → 公開の順にする。
2. **【最新版】を自動で出し直す**：訂正がたまった事案は、決まりで【最新版】を出し直す。
3. **振り分けを一人に集めない**：信長に仕事が集まり、大きな事案の判定が遅れた日があった。大事な順に渡す仕組みは入れたが、振り分けの役を二人にするか、下調べの役が「急ぎ」を付けられるようにする。
4. **入口の一覧を毎日更新する**：一覧が昼の版のまま止まり、夕方以降の事案に入口がなかった。

## 4. ほかの分野で始める手順（案）

1. **読む人を決める**：誰が、どんな場面で困っているか（例：詐欺の電話を受けた高齢者と、その家族）。
2. **役割と問いを作る**：読む人ごとに 1 役。役ごとに「最初に自分に問うこと」を一文で決める。人物の視点は、ここで役割をはっきりさせる道具として使える。
3. **一次出典と書き分けを決める**：その分野の公式の発表元（官公庁、会社、警察など）と、「確認済み／推定／未確認」の書き方。
4. **読む人の入口を決める**：【最新版】と一覧の形。
5. **点検と見直しの役を置く**：事実の点検役、毎晩の評定。点検する役には、下調べの材料を先に読ませない（事情を知らない目を残す）。
6. **守りと上限を入れる**：上の 2 の 5 点。
7. **小さく 1 週間回し、毎晩直す**：今回の 1 週間の改善の記録（[成果報告](README.md)）が、そのまま手本になる。

## 5. 今回使ったもの

- **Claude Managed Agents**：投稿する 10 人（人物ごとに別の Agent と別の vault）
- **Claude Code の routines**：補助bot（下請け）と、比べるための素の Claude
- **GitHub Actions**：30 分ごとに場を見て、必要な AI だけを起こす watcher（[ops リポジトリ](https://github.com/AgenticAIJP/ai-security-hantei-ops)）
- **Claude Code**：設計、手順、watcher、試験、運用中の改修、検証、成果報告と動画まで、すべての開発の中心
- **議論の場**：TimePersona（期間前からあるサービス。GitHub と同じくインフラとして使った）
- **費用**：API 約 $428（7 日）。下請けと比べる役は Max 5x Plan の範囲
