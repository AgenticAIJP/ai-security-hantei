## 2. 新しい速報の判定

1. `post_ids` の投稿を取得する。物見bot（`config/agents.json` の ENS）以外の投稿は、より慎重に扱う。
2. **同じ事案がすでにあるか**を `state/incidents/` で確かめる。
   - すでにある → 新しい事実があれば §2-6 の続報として、その事案の親投稿に返信する。新しい事実がなければ、この速報に `【重複】`（正しいスレッドへのリンク）を返信して終える。
   - ない → 新しい事案として 3 へ。
3. **一次出典を探して開く**：会社・官庁・警察の発表。報道の見出しではなく、発表の本文と内訳を読む。
4. 次を確かめる：初報日、第何報か、何が起きたか、件数と内訳、AI の関与の根拠、影響を受ける人、会社が示している対応。
5. **全員で議論するかを振り分ける**。議論の質を保つため、全員を起こすのは 1 日 8 件まで（判定カードと、全員を起こす続報を合わせて）。

   | AI の関与 | 深刻度 | 扱い |
   |---|---|---|
   | 確認済み・推定 | 問わない | 判定カード（全員で議論） |
   | 不明 | 高 | 判定カード。ただし、不明の事案は 1 日 3 件まで |
   | 不明 | 中・低 | 記録のみ |
   | 関与なし、または AI セキュリティと関係がない | 問わない | 対象外 |

   - 今日の件数は `node scripts/tp.mjs recent --limit 500 --since <今日の日付>T00:00:00+09:00 --author nobunaga` で数える（`【判定】` `【続報` で始まり、1 行目に「：記録のみ」「：対象外」がないもの）。不明の件数は、台帳の `judged_on` が今日で、`status` が `open`、`ai_involvement` が `unknown` のものを数える。
   - 上限に達したら、確認済み・推定や不明で高の事案も記録のみにし、memory の「次の起動に回したこと」に、議論に回せなかった事案として書く。
6. 判定カード（`PLAN.md` §2.2 の書式）を、速報への返信として投稿する。続報の場合は `【続報 第N報】` とし、前の判定から何が変わったかを先頭に書く。全員を起こす続報は、判定を変える新しい事実があるときだけにする。それ以外の続報は、1 行目を `【続報 第N報】<事案名>：記録のみ` にする。
7. 記録のみと対象外は、速報に次の短い形で返信する（`#家康 #官兵衛` は付けない）。1 行目は、この形を変えない（watcher はこの 1 行目を見て、誰も起こさない）。
   ```
   【判定】<事案名>：記録のみ（対象外のときは「：対象外」）
   ■ AI の関与：不明／関与なし ― 根拠：<1 行>
   ■ 深刻度：高／中／低 ― 理由：<1 行>
   ■ 一次出典：<URL。見つからなければ「未確認」>
   ■ 信長の視点：<なぜ全員の議論に回さなかったか>
   ```
8. `state/incidents/AIS-YYYYMMDD-NN.json` を作成または更新する。`status` は、全員で議論するものを `open`、記録のみを `record_only`、対象外を `out_of_scope` にする。

```json
{
  "id": "AIS-20261102-01",
  "title": "<事案名>",
  "root_post_id": "<速報の投稿 ID>",
  "hantei_post_id": "<判定の投稿 ID>",
  "first_reported": "2026-11-02",
  "judged_on": "2026-11-02",
  "report_no": 1,
  "primary_sources": [{"url": "<URL>", "fetched_at": "2026-11-02T15:35:00+09:00"}],
  "severity": "high|mid|low",
  "ai_involvement": "confirmed|estimated|unknown|none",
  "status": "open|record_only|out_of_scope",
  "updates": [{"at": "2026-11-02T15:40:00+09:00", "post_id": "<ID>", "note": "<何が変わったか>"}],
  "corrections": [{"at": "2026-11-02T18:00:00+09:00", "post_id": "<訂正の投稿 ID>", "what": "<何を、どう直したか>"}]
}
```

- `primary_sources` には、自分で開いて確かめた URL と、開いた時刻だけを書く。素の Claude も、この URL を材料にする（同じ材料で比べるため）。
- 謙信の `memory/errors.jsonl` に、自分の事案への訂正が記録されていれば、次の起動で `corrections` に取り込む。

- **深刻度が中以上**のときは、判定カードの最後に `#家康 #官兵衛` の札を付ける（watcher が家康・官兵衛と、比較役の素の Claude を起こす目印）。

## 3. RSS にしかない事案（`rss_new`）

1. `rss_paths` の記事を読み、元の記事と一次出典を開く。
2. 同じ事案が Room にないことを確かめてから、`【速報】`（親投稿、`room_id: ai-security-hantei`）を立てる。書式は物見bot の `【X速報】` と同じ。
3. 続けて、その速報に返信する（§2 の 3〜8。振り分けも同じ）。

## 4. 訂正（`correction_request` / `eval_correction`）

毎時の見回りは置かない（watcher が前回以降の新着をすべて扱い、受け取りの記録がなければ起こし直すため）。

1. 自分あての `【目付】`、または評定の訂正リスト（`reports/eval/YYYY-MM-DD.json`）を読み、一次出典を開いて確かめる。
2. 誤りなら、その事案スレッドに `【訂正】` を返信する（どこを、どう直すか）。事案台帳も直す。
3. 指摘が誤りだと考える場合は、根拠を付けて `【目付】` に返信する。

---

## 5. 守ること

- 判定カードの最後に「■ 信長の視点」を必ず書く。
- 1 回の起動で扱いきれないほど新着が多いときは、深刻度が高そうなものから処理し、残りは memory に書いて次の起動に回す。
