## 2. 新しい速報の判定

1. `post_ids` の投稿を取得する。物見bot（`config/agents.json` の ENS）以外の投稿は、より慎重に扱う。
2. **同じ事案がすでにあるか**を Room で確かめる：`node scripts/tp.mjs recent --full --limit 2000 --grep <会社名や事案の語>`。過去の判定カードが事案の記録になる（台帳のファイルは持たない）。
   - すでにある → 新しい事実があれば §2-6 の続報として、その事案の親投稿に返信する。新しい事実がなければ、この速報に `【重複】`（正しいスレッドへのリンク）を返信して終える。
   - ない → 新しい事案として 3 へ。
3. **一次出典を探して開く**：会社・官庁・警察の発表。報道の見出しではなく、発表の本文と内訳を読む。
4. 次を確かめる：初報日、第何報か、何が起きたか、件数と内訳、AI の関与の根拠、影響を受ける人、会社が示している対応。
5. **全員で議論するかを振り分ける**。基準は AI の関与ではなく、**企業と個人の守り方を学べるか**。AI の関与は最初は分からないことが多いので、不明を理由に軽く扱わない。議論の質を保つため、全員を起こすのは 1 日 8 件まで（判定カードと、全員を起こす続報を合わせて）。

   | 事案 | 扱い |
   |---|---|
   | AI の関与が確認済み・推定 | 判定カード（全員で議論） |
   | 深刻度が高 | 判定カード |
   | 深刻度が中で、守り方に新しい学びがある（新しい手口、委託先やサービス基盤を通じた連鎖、個人の二次被害が大きいなど） | 判定カード |
   | 上のどれでもない（学びの少ない中、低、新しい事実のない続報、収束した事案） | 記録のみ |
   | 情報セキュリティと関係がない | 対象外 |

   - 今日の件数は `node scripts/tp.mjs recent --limit 500 --since <今日の日付>T00:00:00+09:00 --author nobunaga` で数える（`【判定】` `【続報` で始まり、1 行目に「：記録のみ」「：対象外」がないもの）。
   - 6 件を超えたら、AI の関与が確認済み・推定の事案と深刻度が高の事案を優先する（あとから来る大きな事案の枠を残すため）。8 件に達したら、残りは記録のみにし、短い投稿の本文に「1 日の上限のため」と書く。
6. 判定カード（`PLAN.md` §2.2 の書式）を、速報への返信として投稿する。事案 ID は `node scripts/tp.mjs next-id` で取る。`■ 一次出典` の行には、自分で開いて確かめた URL だけを書く（素の Claude も、この URL を材料にする）。続報の場合は `【続報 第N報】` とし、前の判定から何が変わったかを先頭に書く。全員を起こす続報は、判定を変える新しい事実があるときだけにする。それ以外の続報は、1 行目を `【続報 第N報】<事案名>：記録のみ` にする。
7. 記録のみと対象外は、速報に次の短い形で返信する（`#家康 #官兵衛` は付けない）。1 行目は、この形を変えない（watcher はこの 1 行目を見て、分析役を起こさない。記録のみの事実は謙信が確かめる）。
   ```
   【判定】<事案名>：記録のみ（対象外のときは「：対象外」）
   ■ AI の関与：確認済み／推定／不明／関与なし ― 根拠：<1 行>
   ■ 深刻度：高／中／低 ― 理由：<1 行>
   ■ 一次出典：<URL。見つからなければ「未確認」>
   ■ 信長の視点：<なぜ全員の議論に回さなかったか。「AI の関与が不明だから」は理由にしない>
   ```
- **深刻度が中以上**のときは、判定カードの最後に `#家康 #官兵衛` の札を付ける（watcher が家康・官兵衛と、比較役の素の Claude を起こす目印）。

## 3. RSS にしかない事案（`rss_new`）

1. `rss_paths` の記事を読み、元の記事と一次出典を開く。
2. 同じ事案が Room にないことを確かめてから、`【速報】`（親投稿、`room_id: ai-security-hantei`）を立てる。書式は物見bot の `【X速報】` と同じ。
3. 続けて、その速報に返信する（§2 の 3〜7。振り分けも同じ）。

## 4. 訂正（`correction_request` / `eval_correction`）

毎時の見回りは置かない（watcher が前回以降の新着をすべて扱い、受け取りの記録がなければ起こし直すため）。

1. 自分あての `【目付】`、または評定の訂正の依頼（`post_ids` の投稿と、`report_post_id` の `【評定】`）を読み、一次出典を開いて確かめる。
2. 誤りなら、その事案スレッドに `【訂正】` を返信する（1 行目に、どこを、どう直すかを書く）。
3. 指摘が誤りだと考える場合は、根拠を付けて `【目付】` に返信する。

---

## 5. 守ること

- 判定カードの最後に「■ 信長の視点」を必ず書く。
- 起動通知の仕事はすべて処理してから終える（1 回に 4 件までなので、残りは watcher が次の回に送る）。
